# ГТО · Печать удостоверений

Статический сайт для загрузки участников из CSV/Excel, редактирования данных и печати текста на готовых бланках 138 × 99 мм. Для GitHub Pages выберите ветку `main` и корневую папку.

## Локальный запуск

Из корня проекта:

```sh
python3 -m http.server 8950 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8950`. Сборка и серверная база данных не требуются. Участники хранятся в памяти страницы и теряются после перезагрузки; калибровка и название принтера сохраняются в localStorage. Чтение Excel требует загрузки SheetJS с CDN; CSV работает без этой библиотеки.

## Дизайн и 3D

Первый экран объясняет пользу сервиса и ведёт в редактор. На компьютерах знак ГТО и удостоверение отображаются в сцене Three.js; участники не передаются в сцену. На телефонах, при экономии трафика, снижении анимации или ошибке WebGL используется локальная SVG-иллюстрация. Сцена загружается отдельно, ограничена 30 кадрами в секунду и останавливается вне экрана и в фоновой вкладке.

Для изменения 3D-сцены нужен Node.js 22+:

```sh
npm ci
npm run check
npm run build
```

Исходник: `src/hero-3d.js`. Сборка: `assets/hero-3d.js` (включена в Git для публикации через GitHub Pages). После изменения исходника пересоберите и сохраните оба файла. Лицензия Three.js: `docs/THREE-LICENSE.txt`. Визуальная система описана в [docs/design.md](docs/design.md).

После изменения CSS, JS или SVG также выполняйте `npm run build`: он добавляет к ссылкам в HTML и динамическому импорту 3D версии по содержимому файлов. Это предотвращает смешивание новой разметки со старым CSS из кеша. Сохраняйте обновлённые `index.html` и `assets/experience.js` вместе с изменёнными ресурсами.

## Положение текста

В разделе «Настройка шаблона» перетаскивайте поля мышью или пальцем. Изменения сохраняются автоматически. Для подстройки выделите поле и нажимайте стрелки (0,2 мм), с Shift — 1 мм. Esc отменяет текущее перетаскивание. Пустое поле на макете обозначается своим названием; это название не печатается. Координаты и размер шрифта доступны в раскрывающейся «Точной настройке».

## Проверка интерфейса

Понадобятся Python Playwright и Chromium. При работающем локальном сервере:

```sh
python3 -m pip install playwright
CHROMIUM_PATH=/usr/bin/chromium python3 tests/smoke.py
CHROMIUM_PATH=/usr/bin/chromium python3 tests/drag.py
CHROMIUM_PATH=/usr/bin/chromium python3 tests/experience.py
CHROMIUM_PATH=/usr/bin/chromium python3 tests/template.py
```

`CHROMIUM_PATH` позволяет указать другой путь к установленному Chromium. Проверяются поиск, редактирование, CSV с кавычками и переносами строк, ошибки импорта, экранирование HTML, сохранение настроек, недоступное хранилище, печатный макет и адаптивность на четырёх ширинах экрана. Скриншоты сохраняются в `/tmp/gto-desktop.png` и `/tmp/gto-mobile.png`.

`tests/drag.py` проверяет перетаскивание при разных масштабах и смещениях принтера, сенсорный ввод, управление стрелками, отмену, границы макета, сохранение и соответствие печатных координат.

`tests/experience.py` проверяет первый экран, WebGL, переходы в редактор, мобильную версию без загрузки Three.js, снижение анимации, потерю контекста и недоступную 3D-сборку. Скриншоты: `/tmp/gto-premium-desktop.png` и `/tmp/gto-premium-mobile.png`.

`tests/template.py` проверяет полный текст награждения в обоих макетах, отсутствие наложений при начальной калибровке, сохранность ранее заданных координат и совпадение положения данных в предпросмотре и печати. Фоновый текст бланка не печатается и не участвует в расчёте координат полей. Схема помогает при настройке, но не заменяет измерение оригинала: размеры нельзя точно восстановить по фотографии с перспективой.

Проверка печати автоматизирована до вызова системного диалога и размеров CSS-макета. Перед тиражом сделайте пробную печать на своём принтере при масштабе 100%, без колонтитулов. Импорт Excel и реальная печать требуют отдельной ручной проверки.
